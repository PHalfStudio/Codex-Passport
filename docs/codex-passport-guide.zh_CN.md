# Codex Passport（设备控制面板）

这是面向 FoloToy AI Passport（目标设备）的非官方兼容固件：ESP32-C3（主控）、8MB 闪存、无外部内存，竖屏 240×320。开机直接进入重新设计的控制面板，不进入原有硬件测试菜单。只使用 UP（上键）、DOWN（下键）和 OK（确定键），不需要触摸、无线局域网、凭据、云端转发、外置键盘或电脑端自定义桥接。

协议依赖厂商未公开的实现，桌面应用更新可能影响兼容性；不能保证所有版本自动识别。兼容名称和标识仅供个人互操作实验，不代表官方设备。目标是 ChatGPT Desktop（桌面应用）的本地功能，不是 Codex CLI（命令行工具）的原生硬件配对。**编译成功、蓝牙连接成功，都不等于桌面应用识别成功。**

## 三键操作

| 实体操作 | 正常页面中的作用 |
| --- | --- |
| 上键、下键短按 | 上一个、下一个焦点，页内循环 |
| 上键、下键按住至少 500 毫秒 | 上一页、下一页，每次按住只切换一次 |
| 确定键按下、松开 | 发送同一个虚拟键的按下、松开 |
| 确定键持续按住 | 保持按下，不自动重复或提前松开 |
| 快速连续点击确定键两次 | 原样发送两组按下、松开，由电脑解释双击 |

三页依次循环：AGENTS（会话）→ COMMANDS（命令）→ NAV / DIAL（方向与旋钮）。每页保留自己的焦点。绿色边框表示本机焦点，白色表示按下，橙色表示本机确认；电脑会话状态使用独立的颜色标记。没有电脑状态时显示中性灰色。

屏幕命令标签表示出厂默认映射，电脑可以重新分配位置。固件只发送位置标识，不自行执行对应电脑命令。

| 屏幕标签 | 协议标识或消息 | 按下 | 松开 |
| --- | --- | --- | --- |
| Agent 1（会话1） | AG00（第1键），ag=0（槽位0） | act=1（按下） | act=0（松开） |
| Agent 2（会话2） | AG01（第2键），ag=1（槽位1） | 按下 | 松开 |
| Agent 3（会话3） | AG02（第3键），ag=2（槽位2） | 按下 | 松开 |
| Agent 4（会话4） | AG03（第4键），ag=3（槽位3） | 按下 | 松开 |
| Agent 5（会话5） | AG04（第5键），ag=4（槽位4） | 按下 | 松开 |
| Agent 6（会话6） | AG05（第6键），ag=5（槽位5） | 按下 | 松开 |
| Fast（快速模式） | ACT06（固定命令位置） | 按下 | 松开 |
| Approve（审批通过） | ACT07（固定命令位置） | 本机确认后按下 | 松开 |
| Decline（审批拒绝） | ACT08（固定命令位置） | 本机确认后按下 | 松开 |
| Fork（分支会话） | ACT09（固定命令位置） | 按下 | 松开 |

| Dial Click（旋钮按下） | ENC_CLK（旋钮标识） | 按下，长按保持 | 松开 |
| Settings（设置） | 导航页最后一格，仅本机操作 | 松开后打开侧边栏 | 不发送远端事件 |

通过、拒绝默认需要在三秒内按两次确定键。第一次不会发送电脑命令；导航、超时、切页、断线都会取消确认。CONFIG_CODEX_PROTECT_FORK_SEND（额外保护配置）可以让分支会话和发送也需要确认。

麦克风控制的是**电脑的麦克风**，不会上传设备内置麦克风音频。双击保留真实按键时序，两个点击需落在电脑约 350 毫秒的窗口内。没有可靠的电脑反馈时，屏幕不会宣称正在录音。旋钮长按不承担本机导航；默认使用真实设备记录的旋钮标识。只有实测证明有必要时，才启用 CONFIG_CODEX_DIAL_LEGACY_ALIAS（旧标识兼容配置）。

## 本机侧边栏

在方向与旋钮页选择“设置”，点击确定键呼出侧边栏；没有蓝牙主机也可使用。上、下键选择条目，确定键进入。原有麦克风、旋钮长按不变。

- Screen Off（关屏）：关闭面板显示与背光，蓝牙和按键扫描继续运行。下一次按键仅唤醒屏幕，整组按下、松开都不会触发远端控制或导航。这不是锁定电脑，也不是主控深睡。
- Brightness（亮度）：上键增加5%，下键降低5%，限制在10%至100%；确定键返回。
- Re-pair（重新配对）：三秒内再次按确定键确认。先断开连接、停止广播，再移除已保存主机，核对控制器移除结果，清除协议栈的配对与通知记录，重新读取存储，并检查持久化记录名称。保留本机身份和应用设置。成功后恢复广播；失败会明确显示，不宣称已经清除。电脑端也需忽略旧设备。
- Diagnostics（诊断）：查看加密、通知订阅、通信容量、电量、充电未知状态、接收错误与丢弃计数、发送失败计数，以及经过字符过滤的方法名。确定键返回。
- Back（返回）：关闭侧边栏，关闭时的松开事件不会触发虚拟按钮。

页面、焦点、亮度在十秒无输入且没有按住键时批量保存，保存过程不持有界面锁。确认状态、按下状态和电脑灯光状态不持久化。非易失存储初始化失败时不会自动擦除数据。

## 软件结构和通信

应用初始化、输入队列、偏好保存和电池任务在 `main/codex_app.c`。输入状态机在 `main/codex_input.c`，侧边栏和唤醒事件处理在 `main/codex_local.c`，固定键位映射在 `main/codex_virtual_keys.c`。蓝牙服务和串行工作任务在 `main/codex_ble_hid.c`，连接代次检查在 `main/codex_ble_link.c`，报文与请求处理在 `main/codex_protocol.c`。状态快照和灯光计算在 `main/codex_state.c`，独立界面在 `main/codex_ui.c`。

按键回调只入队。32项蓝牙队列串行处理通知和请求；特征值回调不解析数据、不读取电池、不绘制界面。断线、协议栈重置、订阅丢失会使旧连接代次和重组缓存失效。延迟超过250毫秒的旧按下事件会丢弃，离线操作不会留待重连触发。通知失败或失去松开事件的发送路径时结束连接。

板级按键只增加了共享电压读数的稳定性和身份检查：必须先确认松开才能接受另一按键，没有创建第二个模数转换驱动，也没有改引脚。现有板级代码已将 BSP_BTN_RELEASE（松开事件）完整注册到 BUTTON_PRESS_UP（真实抬起事件）。

| 兼容身份 | 值 |
| --- | --- |
| 名称、制造商 | Codex Micro（兼容名称）、Work Louder（兼容制造商） |
| 即插即用来源、厂商、产品、发布标识 | 02、303A、8360、0101 |
| 即插即用值，小端格式 | `02 3A 30 60 83 01 01` |
| 用途页、应用用途、报告编号 | FF00、01、06 |
| 人机接口、电池、设备信息服务 | 1812、180F、180A |
| 输入、输出报告引用 | `06 01`、`06 02` |
| 输入、输出特征值 | 63字节正文，不包含报告编号 |
| 安全 | 安全连接、16字节加密密钥、持久配对、单主机 |

Just Works（无配对码配对）缺少配对码和中间人验证，应在可信环境首次配对。报告读写和通知订阅写入需要加密，配对由 NimBLE（低功耗蓝牙协议栈）保存。只支持报告模式，不支持启动键盘模式，不模拟普通键盘或有线键盘。

HID Information（人机接口信息）是 `11 01 00 02`。完整 HID Report Map（报告描述表）如下：

```text
06 00 FF 09 01 A1 01 85 06 15 00 26 FF 00 75 08 95 3F
09 02 81 02 95 3F 09 03 91 02 C0
```

每个正文由消息类型02、分片长度0至61、文本分片和补零组成。发送追加换行，按61字节顺序分片，在工作任务中间隔4毫秒。接收兼容63字节正文、带06前缀的64字节值、两种常见换行，以及无换行但完整的数据对象。重组上限4096字节，嵌套上限16层，结构标记上限256，超时2.5秒；检查文本编码，并在解析错误或识别到新顶层请求时恢复。支持连续多条消息。协议没有序号，无法保证检测到所有丢失分片。

| 电脑请求 | 固件处理 |
| --- | --- |
| sys.version（版本查询） | 返回实际固件版本 |
| device.status（设备状态） | 版本、档案0、层1、电量、充电状态 |
| v.oai.thstatus（会话灯光） | 独立更新六槽颜色、亮度、效果、速度及已知扩展字段 |
| v.oai.rgbcfg（灯光配置） | 保存两区域配置，环境色用于屏幕装饰线 |
| host.focused_app（焦点应用）、lights.preview（灯光预览） | 兼容应答，不保存私人内容 |
| 带请求编号的未知方法 | 返回−32601和方法不存在；非法参数使用−32602 |

接收标准字段与紧凑别名，回复保留字符串、数字或空值请求编号；没有编号的通知不回复。支持数字0、4及名称形式的关闭、呼吸效果；未知效果降级为静态颜色。只有有效请求交互才显示 Host Active（主机已交互），这仍不能证明主机就是桌面应用。

按键是否可发送单独判断：已加密、已订阅通知、通信容量至少66字节、连接可用即可，不再要求先收到电脑请求。这样支持桌面的仅输入模式，也不会误报请求通信成功。正在关闭的连接不能被电脑的恢复命令重新启用。

0.1.1版本修正了认证配置冲突：sm_sc_only（协议栈安全连接专用开关）还会强制要求带身份认证的四级属性访问，但本机采用的免配对码方式不能满足。现已关闭该开关；构建仍禁用旧式配对，保持安全连接，报告及通知订阅仍要求加密。

电量由独立任务每15秒读取实际电量计。失败时返回 battery:null（电量未知）及 battery_available:false（采样不可用），电池服务不会编造数值。板级代码没有充电状态接口或引脚定义，因此返回 is_charging:null（充电未知）和 charging_available:false（充电状态不可用）。未知状态会明确报告，不使用虚构读数替代。

界面内存池32KiB，沿用单个40行的16位颜色显示缓冲，约19.2KB。没有在目标设备分配全屏缓冲、外部内存或音频流。固定接收、回复缓冲约8.7KB；任务栈和解析对象使用内部内存。运行日志包含可用内存、历史最少内存、最大连续块和应用栈余量；这些日志用于设备诊断。

## 编译、验证与刷机

按上游工程说明激活 ESP-IDF 5.5.3（仓库锁定的开发框架）。依赖锁文件和8MB最小分区表没有修改。在工程根目录执行：

构建标识和标准镜像前缀沿用 FoloToy-AI-Passport（仓库原名称），以复用校验与归档工具；应用产品和开机界面是本项目的控制面板。发布附件可将已验证的完整镜像重命名为 `full.bin`（完整固件）。

```bash
idf.py build
./tools/validate.sh
CODEX_SANITIZE=1 ./tools/test_codex.sh build/codex-sanitizers
```

以上分别是编译、完整验证、内存安全检测。完整验证包括仓库检查、主机测试、隔离编译、真实图形库的主机渲染、合并镜像和对应调试文件校验。纯逻辑与模拟蓝牙测试无需设备或开发框架；主机测试解析库的来源记录在 `tests/vendor/cjson/README.zh_CN.md`。界面渲染需要编译生成的锁定图形库、本机编译器和构建工具。

使用 `build/FoloToy-AI-Passport-full.bin`，刷入偏移 **0x0**。不能将只有应用程序的镜像刷到这个偏移。完整验证保留对应的应用、引导程序、分区表和调试文件；目录为 `build/firmware/<完整镜像校验值>/`。校验该目录的命令是：

```bash
python3 tools/archive_firmware.py verify build/firmware/<full-image-sha256>
```

这里的占位符表示完整镜像的 SHA-256（安全散列校验值）。**验证命令不刷机。**只有明确授权之后，确认实际串口，再执行：

```bash
python -m esptool --chip esp32c3 --port PORT --baud 460800 \
  write_flash --flash_mode dio --flash_size 8MB --flash_freq 80m \
  0x0 build/FoloToy-AI-Passport-full.bin
idf.py -p PORT monitor
```

PORT（实际端口占位符）需替换为设备的 USB Serial/JTAG（原生开发串口）端口，第二条命令查看日志。合并镜像的填充区可能重置保存的偏好和配对信息，需要保留的数据应先另行保存；保留旧数据可能需要兼容的分段刷入。不会执行整片擦除，也不将读取原固件备份作为前置条件。脚本不会发布或推送固件、调试文件和日志。

## 0.1.1版本的认证故障修复

只读检查确认，旧固件在电脑上正确枚举为厂商303A、产品8360、用途页FF00、应用1，包含报告编号后的输入输出长度均为64字节。但系统日志对输入通知订阅和输出报告写入都返回 Authentication is insufficient（认证不足）。这解释了设备已加密、未订阅、接收数为零，以及桌面显示功能受限。

锁定开发框架的真实权限检查函数在修复前重现故障，修复后通过；原先仅模拟无线接口的测试未覆盖这一问题。完整验证现增加真实框架权限函数测试，确认免配对码加密连接可访问、未加密和报告密钥过短仍被拒绝。没有将桌面应用的私有实现加入固件。

授权更新后，应检查 NTF yes（已订阅）、接收计数增加及真实按键操作。仍残留旧缓存时，在电脑上忽略设备，再通过本机重新配对确认操作连接。设备所有者已确认 1.0.0 版本全部功能的设备与桌面应用实测通过。

## 电脑与实机验收清单

设备所有者已确认全部功能正常。以下清单保留供后续版本回归测试使用。

1. 编译并校验固件，取得设备所有者授权后刷入。
2. 检查开机进入新控制面板，没有原测试菜单。
3. 检查 Advertising（广播中），电脑蓝牙设置可发现兼容名称。
4. 在可信环境配对，核对电脑实际枚举的厂商303A、产品8360、用途页FF00、报告编号6，不能只看源码常量。
5. 打开桌面应用，按提示授予 Input Monitoring（输入监控）权限。
6. 打开 Settings → Codex Micro（设置中的设备页面），确认应用发现设备。
7. 检查设备状态查询往返、主机已交互、加密、通知订阅和至少66字节的通信容量；仅蓝牙连接不算应用识别。
8. 检查六个会话键、单击和双击，以及切回页面时的焦点。
9. 检查快速模式、确认后的通过和拒绝、分支会话、发送；检查取消和超时。
10. 检查电脑麦克风按住录音、松开停止、双击锁定、再次点击停止。
11. 检查四个方向、松开归零，再次触发同一方向。
12. 检查旋钮每次点击只有一个刻度，以及超过500毫秒的旋钮按住行为。
13. 检查六槽颜色独立更新、亮度、关闭和低频呼吸。
14. 检查实际电量、充电未知状态、按住时断线、恢复广播与订阅、断电后复用配对。
15. 检查侧边栏亮度保存、关屏和唤醒不误触、重新配对确认、电脑忽略旧设备后再次配对。

蓝牙已连接但应用未识别时，依次检查：

| 检查项 | 应看到的证据 |
| --- | --- |
| 即插即用字节序与枚举 | 电脑观察到正确厂商、产品，七字节值正确 |
| 报告描述表和报告引用 | 用途页FF00、应用1、编号6、输入输出63字节 |
| 通知订阅、通信容量 | 通知已订阅、已加密、容量至少66 |
| 访问权限和连接安全 | 安全连接加密完成，不只是普通连接 |
| 设备状态查询 | 请求及相同编号的回复、接收计数增长、没有发送失败 |
| 旧描述表缓存 | 电脑忽略旧设备，设备侧重新配对，再连接 |
| 输入监控权限 | 在隐私与安全中启用桌面应用的权限，再重启应用 |
| 双方日志 | 比较固件方法、错误、输入延迟日志与桌面诊断 |

本机可执行 `ioreg -r -c IOHIDDevice -l`（读取枚举信息），不要共享无关设备标识。只读串口枚举不构成刷机授权。旧固件的电脑枚举及故障已只读检查；1.0.0 版本的功能验收随后由设备所有者确认通过。
