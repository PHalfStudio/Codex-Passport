## 配对权限回归

此前对旧固件的只读检查确认，电脑枚举的厂商编号为 0x303A、产品编号为 0x8360、用途为 FF00/01、报告编号为 6。系统日志在订阅输入通知和访问输出报告时均记录 Authentication is insufficient（认证不足），错误码为 5。这与设备已加密、没有通知、没有收到请求的现象一致；仅正确枚举不代表控制可用。

指定框架中的 `sm_sc_only=1`（仅安全连接开关）还会要求四级已认证访问，而无配对码方式虽然加密，并不满足这里的已认证条件。0.1.1 使用 `sm_sc=1`（启用安全连接）、`sm_sc_only=0`（关闭额外限制）及二级安全。构建仍禁用传统配对，报告和通知配置仍要求加密及 16 字节密钥。

回归测试从已启用的框架中提取三个未经修改的权限函数，保留许可声明，复现原故障并检查加密访问成功、未加密拒绝及短密钥拒绝。此前不依赖框架的模拟测试没有发现此问题；新测试仍不能替代无线实测。

输入就绪现在要求连接可用、加密、已订阅且传输长度足够，不再要求先收到电脑请求。界面中的主机活跃状态仍需有效请求。关闭中的连接不会被电脑恢复请求重新打开。

## 重现与保留产物

启用指定框架后，在仓库根目录运行上述命令。完整验证生成 `build/FoloToy-AI-Passport-full.bin`（完整固件）及 `build/firmware/<full-image-sha256>/`（按校验值归档的调试包）。

```bash
python3 tools/archive_firmware.py verify build/firmware/<full-image-sha256>
```

发布时保留匹配的调试符号、内存映射和清单，不同编译时间生成的符号不能混用。不提交构建历史、本机日志和依赖缓存。完整镜像刷入偏移为 `0x0`，可能重置设置及绑定，无需整片擦除。

## 资源检查与实机验收

主机界面测试使用 32 KiB 图形内存池，执行后剩余 5,232 字节，峰值使用 23,568 字节。这不是设备堆内存实测。链接结果为静态内存使用 154,058 字节、运行时分配前剩余 167,238 字节。设备使用现有 19.2 KB 局部显示缓冲，不使用全屏缓冲。

旧固件的枚举及认证错误经过只读观察，设备所有者已确认 1.0.0 版本全部功能通过实机验收。[完整手工清单和排查表](codex-passport-guide.zh_CN.md)覆盖开机、屏幕、全部按键、通知和请求响应、电脑麦克风行为、重连、绑定复用、电量、未知充电状态、亮度和唤醒。刷写必须取得设备所有者明确授权。
